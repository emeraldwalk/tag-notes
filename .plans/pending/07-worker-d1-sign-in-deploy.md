### `worker/wrangler.jsonc`

- `name: "tracker"`, `main: "src/index.ts"`, a current `compatibility_date`, `compatibility_flags: ["nodejs_compat"]`.
- `workers_dev: false`, `preview_urls: false`, `observability: { enabled: true }`.
- `routes: [{ "pattern": "tracker.ingles.place", "custom_domain": true }]`.
- `d1_databases: [{ binding: "DB", database_name: "tracker", database_id: "<owner fills in>", migrations_dir: "migrations" }]`.
  Commit a placeholder id with a comment saying the owner replaces it after `npx wrangler d1 create tracker`.
- `vars`: `IDP_ISSUER: "https://auth.emeraldwalk.com"`, `TZ_NAME: "America/Chicago"`.
- Secrets (documented in a comment and in `src/env.d.ts` or the generated types): `IDP_CLIENT_ID`,
  `IDP_CLIENT_SECRET`, `COOKIE_SECRET`.

### Sign-in

`createAuthClient` per isolate with redirect URI `https://tracker.ingles.place/auth/callback`, post-logout
`https://tracker.ingles.place/`, `cookieName: "tracker_session"`, and
`session: { idleSeconds: 2_592_000, maxSeconds: 2_592_000 }` (30 days, owner's choice). Mount `authRoutes` at `/`.

Who may sign in is controlled by the app's access in the IdP console, not by a list in the Worker. Rows the later
plans write carry `user_id` = the session's IdP subject (`session.sub`).

### Routes

| Route | Auth | Response |
| --- | --- | --- |
| `GET /auth/login`, `/auth/callback`, `/auth/logout` | — | `authRoutes` |
| `GET /` | signed in, else 302 to login with `returnTo` | Small HTML page: "Tracker", the user's name, their user id (`sub`, so the owner can copy it for plan 14), the build's commit, and a sign-out link |
| `GET /api/me` | signed in, else `401 {"error":"unauthenticated"}` (JSON, no redirect) | `{ "sub": string, "name": string }` |
| anything else | — | `404` |

API routes answer JSON errors as `{ "error": "<code>" }`. Later plans add routes under `/api/`; keep a single router
module they extend.

The build's commit: Workers Builds sets `WORKERS_CI_COMMIT_SHA` at build time. Bake its first 7 characters in through
wrangler `define` or a generated module; `"dev"` locally.

## Concept boundaries

- **"tracker"** is the Worker name, the D1 database name and the domain. The PWA workspace is `tracker-pwa`, the
  Worker workspace `tracker-worker`. The GitHub repo is still `tag-notes` until after plan 8 (renaming it moves the

## How work ships

Claude commits; the owner pushes. Claude holds no Cloudflare credentials. The owner runs anything needing Cloudflare
access and sets secrets with `npx wrangler secret put <NAME>` from `worker/`.

## Owner steps (README, Deploying)

1. IdP console: register app "Tracker" with redirect URI `https://tracker.ingles.place/auth/callback` and
   post-logout URI `https://tracker.ingles.place/`; give your own account access. Keep the client id and secret.
2. From `worker/`: `npx wrangler d1 create tracker`, paste the id into `wrangler.jsonc`, commit.
3. `npx wrangler secret put IDP_CLIENT_ID`, `IDP_CLIENT_SECRET`, `COOKIE_SECRET` (`openssl rand -base64 32`).
   If the Worker doesn't exist yet, the first `secret put` offers to create it; accept.
4. Workers Builds: new project `tracker` from this GitHub repo, root directory = repo root, production branch `main`,
   build command `npm run build -w tracker-worker`, deploy command `npm run deploy -w tracker-worker`, non-production
   branch builds off.
5. Push `main`.

## Validation (owner, after the push)

1. `https://tracker.ingles.place` → IdP sign-in → placeholder page with your name and id. Note the id (plan 14).
2. Sign out, then back in: silent while the IdP session lasts.
3. The GitHub Pages site still loads and keeps its notes and food.
4. Workers Builds log shows the migrations step ran (nothing to apply).
